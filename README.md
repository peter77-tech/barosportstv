#### 🔴 근본 원인 하나 — 브레이크포인트가 사이드바 폭만큼 어긋난다

Tailwind의 `lg`·`xl`은 **화면 폭** 기준인데, 이 레이아웃의 본문은 **고정 사이드바 256px을 뺀 폭**을 쓴다.
그래서 `xl:`(1280px)이 켜지는 시점의 실제 가용폭은 **1024px**이다. 이 차이가 14·15를 동시에 만들었다.

**규칙: 본문 안의 반응형 판단은 한 단계씩 올려 잡는다.**
가용폭 1024px이 필요하면 `xl`이 아니라 `2xl`에 건다. 나머지 5종도 같은 규칙을 따른다.
(더 정확히 하려면 컨테이너 쿼리로 바꾸면 된다 — `container-queries` 플러그인은 이미 로드돼 있다.)

**검증한 폭**: 1600 · 1440 · 1280 · 1024 · 390 — 전 구간 메뉴 잘림 0 · 그룹 겹침 0 · 가로 스크롤 없음.

## Tailwind 빌드 (2026-08-19 전환 완료)

CDN(`cdn.tailwindcss.com`)을 걷어내고 빌드된 CSS로 바꿨습니다.

```
npm install          # 최초 1회
npm run build:css    # assets/tailwind.css 생성 (28KB, minified)
npm run watch:css    # 저장할 때마다 자동 재빌드
```

| 파일 | 역할 |
|---|---|
| `assets/theme.js` | **디자인 토큰의 유일한 원본.** 색·타이포·간격을 여기서만 고친다 |
| `tailwind.config.js` | 위 파일을 **읽어서** 쓴다. 토큰을 여기에 복사하지 말 것 (갈라진다) |
| `src/input.css` | `@tailwind` 지시문만 있는 입력 파일 |
| `assets/tailwind.css` | **빌드 산출물. 직접 편집하지 말 것** |
| `assets/app.css` | 커스텀 CSS(`.glass-card` 등). 빌드와 무관하게 그대로 유지 |

**토큰을 바꿨으면 반드시 `npm run build:css`를 다시 돌리십시오.** 안 돌리면 화면에 반영되지 않습니다.

- 플러그인: `@tailwindcss/forms`(검색창 `<input>` 6곳에 실제 적용) · `@tailwindcss/container-queries`(현재 미사용)
- `content` 에 `./assets/*.js` 가 들어간 이유: `app.js` 가 `bg-hermes-orange` · `translate-x-1` · `translate-x-6` 를
  JS에서 토글하므로, HTML만 훑으면 그 클래스가 빌드에서 빠집니다.

## 깊이(elevation) 체계 — 2026-08-19 적용

BD 지적: **"너무 평면적이다. 종이 조각을 연결해 놓은 느낌이다."**

원인은 실제로 있었다.

| 원인 | 이전 값 |
|---|---|
| 배경과 카드의 밝기가 거의 같음 | 배경 `#fbf9f9` vs 카드 흰색 70% |
| **테두리가 흰색** — 밝은 배경에서 안 보임 | `rgba(255,255,255,0.4)` |
| 그림자가 한 종류 — 모든 카드가 같은 높이 | `.glass-card` 하나 |
| 구역 구분이 여백뿐 | `section-gap: 80px` |
| `backdrop-filter: blur(12px)` 가 무의미 | 배경이 단색이라 흐릴 것이 없었다 |

### 채택안 (B+C) — 높이 4단

모든 블록이 살짝 뜬다. 값은 `assets/app.css` 의 `:root` 변수에서만 고친다.

| 단 | 대상 | 변수 |
|---|---|---|
| 0 | 배경 (브랜드 광원) | `body::before` |
| 1 | 구역 패널 `.depth-panel` | `--elev-panel` |
| 2 | 카드 `.glass-card` | `--elev-card` |
| 3 | 히어로 · 대표 기사 | `--elev-hero` |
| 보조 | 칩 · 스코어박스 | `--elev-chip` |
| 호버 | 카드 | `--elev-hover` |

셸도 각자 떠 있다 — 사이드바는 오른쪽으로, 상단바는 아래로, 푸터는 위로 그림자를 던진다.

### 규칙

1. **눌린(inset) 그림자를 단독으로 쓰지 않는다.** 파여 보인다. inset 은 위쪽 하이라이트로만 쓴다.
2. **구역 패널은 `.depth-panel` 클래스로 명시한다.** 구조 선택자(`main > section`)를 쓰면 안 된다 —
   중계 화면은 섹션이 그리드 안에 중첩돼 있어 규칙이 빗나갔다.
3. **상단바는 `.app-header` 로 겨냥한다.** 태그 선택자 `header` 를 쓰면 일정·뉴스·대시보드의
   페이지 제목용 `<header>` 에도 붙어 제목 주위에 상자 윤곽이 생긴다.
4. **칩·필터 줄에는 패널을 씌우지 않는다.** 내용 몇 개만 담긴 거대한 빈 판이 된다.
5. **2단 컬럼은 양쪽 다 패널로 맞춘다.** 한쪽만 씌우면 비대칭이 눈에 띈다
   (뉴스의 `많이 본 기사`, 중계 화면의 `다른 경기` 가 그랬다).
6. `glass-card` 는 **밝은 표면 전용**이다. 어두운 배경에는 `bg-white/10` + `backdrop-blur-sm`.

### 좌측 메뉴가 본문을 덮고 있는 느낌 (2026-08-19 추가)

BD 요청: **"좌측 메뉴가 전체의 일부를 포개고 있는 듯이 — 접고 펼치는 것이니 진짜로 펼쳐져서 덮여 있는 느낌"**

핵심은 그림자를 키우는 게 아니라 **사이드바가 본문에 그림자를 드리우게** 하는 것이다.
이전에는 본문이 사이드바 옆에 나란히 있어서 "덮고 있다"는 단서가 아예 없었다.

| 처리 | 내용 |
|---|---|
| 오른쪽 경계 **두 줄** | `inset -1px` 밝은 선(판의 모서리 광택) + 바로 밖 `1px` 어두운 선(판이 끝나는 곳) |
| 본문에 드리운 그림자 띠 | `.main-wrap::before` — `fixed`, **폭 96px**, 사이드바 폭에서 시작해 오른쪽으로 소멸 |
| 넓고 깊은 확산 그림자 | 12px / 34px / 72px 3중 |

#### 세기 조정 (BD 피드백 반영)

1차(띠 60px · 시작 농도 0.22)는 **좁은 창에서는 잘 읽혔지만 넓은 화면에서 약했다.**
창이 넓어질수록 사이드바 비중이 작아져 띠가 얇은 조각처럼 보인다.
→ 띠 **96px** · 시작 농도 **0.34** 로 올려, 그림자가 **첫 카드 위까지** 드리우게 했다.

| 위치 | 1차 | 강화 후 |
|---|---|---|
| 경계 +8px | 128 | **97** |
| 경계 +24px | 185 | **149** |
| 경계 +56px | 232 | **204** |

(밝기 0~255. 낮을수록 어둡다. 964px 창, 확대 없이 1:1 측정)

> ⚠️ 확대한 이미지로 세기를 판단하지 말 것. `9_경계_확대.png` 는 **3배 확대**라 실제보다 뚜렷해 보인다.
> 세기 판단은 **1:1 이미지**(`10_그림자_강화_1대1비교.png`)로 한다.

- 띠는 **`z-index: 45`** — 상단바(40) 위, 사이드바(50) 아래. 상단바에도 그림자가 드리워야
  사이드바가 화면 전체를 덮은 것처럼 읽힌다.
- 접으면 띠도 따라온다 (`left: 256px` → `80px`). 검증: 사이드바 80px · 본문 여백 80px · 띠 80px 일치.
- 사이드바는 `overflow-x: hidden` 이라 **자기 `::after` 로는 밖에 그릴 수 없다.** 그래서 본문 쪽에 깔았다.
- 모바일에서는 띠를 숨긴다 — 사이드바가 화면 밖이라 본문에 얼룩만 남는다 (열렸을 때는 `scrim` 이 그 역할).

측정으로 확인: 경계 직후 밝기 **116** → 70px 뒤 **205** 회복.

적용 결과: `_검토_스크린샷/깊이감적용후/` (본문 6장 + 사이드바 펼침/접힘/경계확대 3장)

### 페이지 전체 여백 (2026-08-19 적용)

앱 전체가 배경 위에 뜬 한 덩어리로 보이게, 사이드바까지 화면 끝에서 띄웠다.

```
화면 끝 -20- [ 사이드바 ] -24- [ 상단바 / 본문 / 푸터 ] -20- 화면 끝
             위아래도 20
```

값은 `assets/app.css` 의 `:root` 에서만 고친다 — `--page` 20px, `--gap` 24px, `--plate` 18px.
상단바·푸터·사이드바 모두 네 모서리를 `--plate` 만큼 깎았고, 상단바의 `sticky top` 도 `--page` 로 내렸다.
모바일(768px 이하)에서는 여백을 없앤다 (사이드바가 드로어이고, 좁은 화면에서 여백은 손해).

#### 그림자 각짐 수정 — 그림자 띠를 없앴다

이전에는 본문 쪽에 별도의 그림자 띠(`.main-wrap::before`)를 깔았다.
사이드바의 `::after` 가 `overflow-x: hidden` 에 잘린다고 봤기 때문인데,
**`box-shadow` 는 `overflow` 에 잘리지 않는다.** 즉 띠는 처음부터 불필요했다.

게다가 사이드바에 `border-radius` 를 준 뒤에는 **네모난 띠가 둥근 모서리를 따라가지 못해**
"그림자가 각지게 나온다"는 지적을 받았다.
→ 띠를 제거하고 사이드바 `box-shadow` 를 **4단 감쇠**로 대체했다.

## 종목 필터 (2026-08-20 적용)

사이드바 종목 링크(NBA·NFL·EPL·MLB·F1)가 `#` 였던 것을 **경기 일정의 종목 필터**로 연결했습니다.
종목별 페이지를 5장 새로 만들지 않은 이유는 공통 셸이 6장에서 11장으로 늘고,
실제 데이터가 없어 내용이 서로 비슷해지기 때문입니다 (BD 결정 2026-08-20).

| 항목 | 내용 |
|---|---|
| 링크 형식 | `schedule.html?sport=<슬러그>` — `nba` `nfl` `premier-league` `mlb` `f1` |
| 경기 행 | `<li data-league="premier-league">` — 이 값과 맞는 행만 남긴다 |
| 리그 칩 | `<button data-league="…">` — 사이드바 종목과 짝을 맞추려 **NFL·F1 칩을 추가**해 8개 |
| 빈 결과 | `.schedule-empty` 안내문("선택한 종목의 경기가 없습니다")을 구역별로 띄운다 |
| LIVE 개수 | 보이는 행만 다시 세고, 0건이면 빨간 LIVE 배지를 감춘다 |
| 주소 | 칩을 누르면 `history.replaceState` 로 `?sport=` 를 갱신 — 새로고침·공유해도 그대로 |

실제 데이터를 붙일 때는 **경기 행에 `data-league` 만 넣어주면** 이 로직을 그대로 씁니다.

### 함정 3가지 (실제로 물렸습니다)

1. **칩이 있는 화면은 경기 일정만이 아닙니다.** 홈(5개)·중계 화면(3개)·뉴스(6개)도
   `.league-chip` 을 씁니다. 필터 로직을 무조건 돌리면 그쪽 칩의 선택 표시가 풀립니다.
   → `li[data-league]` 가 있는 화면에서만 필터로 동작시킵니다 (`filterable`).
2. **`hidden` 속성은 Tailwind 의 `flex` 에 집니다.** 브라우저 기본 `[hidden]{display:none}`
   보다 클래스가 강해서 안 숨습니다. → `app.css` 의 `li[hidden], .depth-panel [hidden]` 로 눌러줍니다.
3. **칩 선택 그림자.** `.league-chip.glass-card` 가 뒤에 있어 선택 상태의 주황 그림자를 덮었습니다.
   → `:not([aria-selected='true'])` 를 붙였습니다.

### 구조 — 점진적 향상

HTML 에 박힌 경기 목록을 **지우지 않았습니다.** 응답이 왔을 때만 다시 그리고,
실패하거나 응답이 비면 하드코딩 목록이 그대로 남습니다. (오프라인·키 만료에도 화면이 안 빔)

| 요소 | 방식 |
|---|---|
| 행 템플릿 | 하드코딩된 행을 **복제해서** 씁니다 — HTML 문자열을 JS 에 또 쓰지 않으므로 스타일이 갈라지지 않습니다 |
| 채우는 자리 | `data-role="time / league / home / away / home-score / away-score / status / action-label / day-title / chip-label / chip-date"` |
| 상태 판정 | `strStatus` + 점수 유무 → `예정` / `진행 중` / `종료` 3가지 |
| 종목 필터 연결 | 행에 `data-league` 를 다시 넣고 `window.ArenaLeagueFilter.reapply()` 로 현재 선택을 다시 적용 |
| 날짜 칩 | 응답이 온 뒤에 실제 날짜로 바꾸고, 누르면 그 날짜 + 다음 날을 불러옵니다 |

### ⚠️ 무료 테스트 키(`3`)의 한계 — 지금 상태

- 날짜+종목 조회가 **3건**까지만 옵니다 (리그별 다음 경기는 1건)
- 그래서 종목 4개(축구·농구·야구·미식축구)를 각각 불러 합칩니다 — UTC 하루 최대 12경기
- 결과적으로 **어떤 리그가 올지 고를 수 없습니다** (USL·아르헨티나 2부 등이 섞여 나옵니다)
- 발급받은 키를 `assets/data.js` 의 `KEY` 에 넣으면 제한이 풀립니다. **코드는 그대로 씁니다.**

### 함정 7가지 (실제로 다 물렸습니다)

1. **응답의 날짜는 UTC 기준입니다.** 그대로 쓰면 한국 새벽 경기가 전날 목록에 붙습니다.
   → UTC 사흘치를 받아 `bucketByLocalDate` 로 현지 날짜에 다시 담습니다.
2. **끝난 경기에 빨간 '진행 중' 배지를 붙이면 안 됩니다.** 점수가 있으면 진행 중으로 보면
   틀립니다 — `종료` 배지 + `경기 기록` 버튼으로 바꿉니다.
3. **필터가 담아둔 행 목록은 다시 그린 행을 모릅니다.** `querySelectorAll` 결과를 변수에
   담아두면 새 행에 필터가 안 걸립니다 → `app.js` 가 매번 다시 찾습니다.
4. **`app.js` 의 경과분 시계가 킥오프 시각을 망가뜨립니다.** `[data-clock]` 은 1분마다
   앞 숫자를 올리므로 `21:30` 이 `24:30` 이 됩니다 → 진행 중이 아닌 경기는 `data-clock` 을
   떼어 내고, `app.js` 도 경과 분 모양(`72'`·`45+2'`)일 때만 올립니다.
5. **자리 이름(`data-role`)이 화면끼리 겹칩니다.** 팀 허브 코드가 `[data-role="team-name"]`
   만 보고 판단해서 **대시보드에서도 돌아** 카드와 문서 제목을 바꿔버렸습니다
   → 팀 허브에만 있는 `h1[data-role="team-name"]` 을 기준으로 잡습니다.
6. **예정 경기에 플레이어의 빨간 'LIVE' 배지가 남습니다.** 화면이 거짓말을 하므로
   상태에 맞춰 `예정`·`종료` 로 바꾸고 시청자 수는 감춥니다.
7. **시즌 개막 전에는 순위가 뜻이 없습니다.** 0경기에 `1위`는 거짓말이라 `–` 로 둡니다.
   또 실제 값을 넣는 순간 채울 수 없는 하드코딩 세부값(`경기당 2.2`·`클린시트`)은 감춥니다 —
   실제 숫자 옆에 남으면 그게 더 나쁩니다.

또 하나: 시간 칸(`<time>`)에 `whitespace-nowrap shrink-0` 이 없으면 리그 이름이 길 때
`종료` 가 한 글자씩 세로로 쪼개집니다.

### 규칙

1. **저장하는 팀 이름은 영문**입니다. TheSportsDB 는 영문으로만 검색됩니다.
   보여줄 때만 `ArenaTeams.ko()` 로 한글로 바꿉니다.
2. **팀 이름 사전은 `assets/teams.js` 한 곳**입니다. `search.js` 도 여기서 읽습니다.
   팀을 늘릴 때 이 파일만 고치십시오 (두 곳에 적으면 반드시 갈라집니다).
3. **스크립트 순서를 지키십시오** — `teams.js` → `app.js` → `search.js` → `user.js`
   → `data.js` → `data-pages.js`. `user.js` 가 「내 팀」 카드를 만들고
   `data-pages.js` 가 그 카드에 실제 일정을 채우므로 순서가 바뀌면 카드가 비어 있습니다.
4. **카드는 하드코딩 카드 하나를 본으로 복제**합니다 (경기 행과 같은 방식).
   HTML 에서 카드 모양을 고치면 저장값으로 만든 카드도 같이 바뀝니다.
5. 첫 방문에는 시연용 4팀(아스날·바르셀로나·레이커스·다저스)을 넣습니다.
   사용자가 **일부러 다 지운 경우**와 구분하려고 `arena.seeded` 표시를 남깁니다 —
   다 지우고 새로고침해도 다시 채워지지 않습니다.
6. 사생활 보호 모드에서는 `localStorage` 접근 자체가 예외를 던집니다.
   그때는 메모리에만 담아 **화면이 죽지 않게** 합니다 (새로고침하면 사라집니다).

### 함정 6가지 (실제로 다 물렸습니다)

1. **같은 성격의 유틸리티는 클래스 순서가 아니라 CSS 파일 순서가 이깁니다.**
   팔로우 버튼에 `bg-hermes-orange` 를 **더하기만** 하면 기본값 `bg-white/10` 에 밀려
   주황이 안 보입니다. 켤 때 `bg-white/10` 을 **빼야** 합니다.
2. **`flex-1` 이 `basis-*` 를 덮어씁니다** (`flex: 1 1 0%`).
   팀 카드 이름칸에 `basis-32` 를 주면서 `flex-1` 을 남기면 이름칸이 0 으로 쪼그라들어
   `아...` 로 잘립니다. `flex-1` 을 떼고 `grow` 를 쓰십시오.
3. **카드 안의 버튼은 덮개 링크 위로 올려야 눌립니다.** 홈 경기 카드는 카드 전체를
   덮는 `<a class="card-link">`(`z-index: 1`)로 이동합니다. 그 안에 버튼을 넣으면
   덮개에 가려 안 눌립니다 → 버튼에 `position: relative` + `z-index: 2` 를 줍니다.
   (2026-08-21 이전에는 `app.js` 가 카드 클릭을 직접 처리했고, `<button>` 이
   `closest('a')` 검사에 안 걸려 알림을 누르면 중계 화면으로 넘어가 버렸습니다.)
4. **경기 행은 `data.js` 가 다시 그립니다.** 버튼에 리스너를 직접 달면 새로 그린 행에는
   안 걸립니다 → `document` 위임으로 받고, 다시 그린 뒤 `repaintNotify()` 로 상태를 입힙니다.
5. **관심 경기 버튼은 상태마다 요소 종류가 다릅니다.** 진행 중·종료는 `<a>`(이동),
   예정은 `<button>`(저장). 글자와 색만 바꾸면 예정 경기에 주황 재생 버튼이 남거나
   알림 버튼이 링크로 남아 눌렀을 때 화면이 넘어갑니다 → 통째로 다시 만듭니다.
6. **팀을 순서(`i`)로 찾으면 안 됩니다.** 팀을 지우면 카드와 목록이 어긋납니다.
   카드에 박은 `data-team`(영문 팀명)으로 찾습니다.

### 규칙 — 화면에 없는 것을 알려주지 않는다

1. **하드코딩 경기를 JSON-LD 로 박지 않습니다.** 화면은 실제 데이터로 바뀌는데
   구조화 데이터만 남으면 검색엔진에 **없는 경기**를 알려주게 됩니다.
   그래서 `assets/seo.js` 가 **응답이 온 뒤에** 만들어 붙입니다.
2. **`BroadcastEvent`·`offers` 를 넣지 않습니다** — 방송권 계약이 없습니다 (BD 항목).
3. **`eventStatus` 는 예정 경기에만** 붙입니다. schema.org 에 '종료' 상태가 없습니다.
4. **`SearchAction` 을 뺐습니다.** 검색 결과 페이지를 만들지 않기로 했으므로(BD 결정
   2026-08-20) 넣어두면 크롤러가 없는 주소를 찾아갑니다.
5. **뉴스 화면은 넣지 않습니다.** 기사가 자리표시자 문구라 `NewsArticle` 로 표시하면
   허위 기사를 등록하는 셈입니다 (뉴스 출처는 BD 판단 항목).
6. **`url` 은 지금 열린 주소를 기준으로 계산**합니다 — 배포하면 자동으로 실제 주소가
   됩니다. 정적 `WebSite`·`canonical` 의 `example.com` 만 배포 시 바꾸면 됩니다.
7. 같은 이름(`data-seo`)으로 다시 부르면 **갈아끼웁니다** — 날짜 칩을 누를 때마다
   쌓이지 않게 합니다.

### 함정 2가지 (실제로 물렸습니다)

1. **`leagueLabel()` 을 구조화 데이터에 쓰면 안 됩니다.** 좁은 칸에 맞춰 줄인 표시용
   값이라('Vietnam Basketball Association' → 'Basketball Association') 잘린 이름을
   알려주게 됩니다. 원문 `strLeague` 를 씁니다.
2. **연고지를 `foundingLocation` 에 넣으면 안 됩니다** — 그건 **창단지**를 뜻합니다.
   응답에 창단지가 없으므로 홈 구장만 `location` 으로 넣습니다.

### ⚠️ 홈 경기 카드 내부 배치 — 카드 폭 하한이 있습니다 (2026-08-21, 5차)

카드 한 줄은 `배지 48 + 팀명 + 점수판 + 팀명 + 배지 48` 입니다.
**점수판 폭이 점수 자릿수에 따라 변합니다** — `0 - 2` 112px / `46 - 16` 148px /
`108 - 102` **172px**. 그래서 카드 폭 하한이 두 개입니다.

| 기준 | 필요 카드폭 |
|---|---|
| 배지·점수판이 겹치지 않을 최소 | **292px** (실제 데이터) · **316px** (세 자리 점수) |
| 팀명이 읽힐 최소 | 약 **380px** |

  40+40=80% 인데 점수판이 고정폭이라 합이 카드를 넘어 **옆 카드에 깔립니다**(최대 136px).

## API 키 다루는 법

키는 **브라우저 코드에 절대 들어가지 않습니다.** 빌드할 때 `tools/prebake.mjs` 만
API 를 부르고, 브라우저는 그 결과인 `data/**.json` 만 읽습니다.

| 어디서 | 주는 방법 |
|---|---|
| 배포 (GitHub Actions) | 저장소 Secret `SPORTSDB_KEY` — 워크플로가 env 로 넘긴다 |
| 로컬 — 한 번만 | `SPORTSDB_KEY=키 npm run prebake` |
| 로컬 — 저장해 두고 쓰기 | 폴더에 `.env` 를 만들고 `SPORTSDB_KEY=키` 한 줄 |

`npm run prebake` 는 `node --env-file-if-exists=.env` 로 돌기 때문에 `.env` 가 있으면
읽고, 없으면 그냥 넘어갑니다. **환경변수가 `.env` 보다 우선**이므로 CI 의 Secret 이
언제나 이깁니다.

> 🔴 **`.env` 는 커밋하지 마십시오.** 저장소가 공개입니다. `.gitignore` 로 막아 뒀지만
> `-f` 로 강제 추가하면 뚫립니다. 키가 새면 TheSportsDB 에서 새 키를 발급받으십시오.
> 무료 테스트 키 `3` 은 공개돼도 무해합니다 (누적 쿼터가 있어 데이터가 들쭉날쭉합니다).
