# 워드프레스 경기 리뷰 자동 발행 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** KBO·K리그1·KBL·WKBL·V리그(남·여)의 끝난 경기마다, 네이버 경기 검색어를 제목에 그대로 담은 사실 기반 리뷰를 AI 가 쓰고 AI 가 검토해 barosportstv.com 에 자동 발행한다.

**Architecture:** `tools/review/` 아래 Node 모듈들. 리그별 수집기가 원본 기록을 공통 `MatchFacts` 로 바꾸고 → 네이버 검색어와 짝지어 제목을 만들고 → 쓰는 AI·코드 검사·검토 AI(1회 재작성) → 코드가 표·점수판·JSON-LD 를 그려 본문을 완성 → 워드프레스 REST 로 발행. `deploy.yml` 과 분리된 `review.yml` 이 30분마다 돈다.

**Tech Stack:** Node 24 (ESM, `node:test`), `sharp`(대표 이미지), Anthropic Messages API(스트리밍, fetch 직접), WordPress REST + 애플리케이션 비밀번호, Rank Math, PHP 8.3(테마 테스트).

**Spec:** `docs/superpowers/specs/2026-10-22-wp-경기리뷰-자동발행-설계.md` — 실행자는 계획과 함께 읽는다. 절 번호(§)는 이 문서를 가리킨다.

## Global Constraints

- 시작일 `START_DATE = '2026-10-22'`(KST). 이날 이전 경기는 절대 쓰지 않는다 (§3).
- 대상: KBO(정규+포스트시즌), K리그1, KBL, WKBL, V리그 남자부·여자부. **컵대회(KOVO컵 등)·K리그2·해외 제외** (§3).
- 제목 = `` `${titleName} ${naverQuery} 경기 리뷰` `` — `naverQuery` 는 네이버에서 뽑은 문자열을 **한 바이트도 바꾸지 않는다** (§6).
- 제목 앞 리그명: `KBO리그` · `K리그1` · `KBL` · `WKBL` · `V리그 남자부` · `V리그 여자부` (§5.1).
- KBO 본문 재료는 **TheSportsDB 만**. `koreabaseball.com` 에 요청을 보내는 코드를 쓰지 않는다(링크만 허용) (§3, §5.2).
- 네이버에서는 **검색어만** 가져온다. 본문 재료로 쓰지 않는다 (§3).
- 공식 사이트 요청 사이 최소 700ms, 끝난 경기만, 경기당 필요한 호출만 (§5.2).
- 표·점수판·비교 막대·선수 표·JSON-LD 는 코드가 그린다. AI 는 문장 필드만 쓴다 (§7.1).
- FAQ 절·FAQPage 스키마 없음. Article 스키마는 Rank Math 몫 — 우리는 SportsEvent 만 (§3, §12).
- 내부 링크 주소는 코드의 표에서만 나온다. 리뷰 외 링크 3~4개, 외부 링크 1개(공식 기록 페이지) (§8).
- 새 Tailwind 클래스 금지. 리뷰 스타일은 테마의 일반 CSS 파일로 (§12).
- 비밀값은 출력·커밋 금지(공개 저장소). `.env` 는 저장소 밖으로 나가지 않는다.
- Anthropic 호출은 **스트리밍**(비스트리밍은 긴 응답에서 `UND_ERR_SOCKET`) (§9). 모델 `claude-sonnet-5-5`(쓰기·검토).
- 한 회차 새 글 최대 `MAX_POSTS_PER_RUN = 12` (비용 상한, AI 판단).
- 🔴 대표 이미지 배경 6장은 **BD 승인 전에는 공개 발행 금지**(Task 11 게이트) (§11).
- 커밋 메시지 끝: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`

## Review Focus

1. **연기·취소·서스펜디드 경기** — 상태가 「종료」가 아니면 리뷰를 쓰지 않는다. → 각 수집기 Task 의 `listFinished` 테스트에 「종료 아님」 표본이 빠지는지 단언.
2. **무승부**(K리그 2-2, KBO 무승부) — 점수판에 「승」 표시가 없고, 이미지·본문이 승자를 지어내지 않는다. → Task 10 `draw_has_no_winner_badge`, Task 8 `draw_no_winner_words`, Task 11 `card_text_draw`.
3. **같은 날 같은 두 팀 경기 2개**(KBO 더블헤더) — 검색어 짝이 둘이면 둘 다 건너뛴다. → Task 2 `match_ambiguous_returns_null`.
4. **네이버 페이지 구조가 바뀌어 검색어를 0개 뽑음** — 조용히 건너뛰지 말고 실행 요약에 오류로 남기고 워크플로를 실패시킨다. → Task 13 `naver_zero_entries_is_error`.
5. **워드프레스 중간 실패**(이미지 업로드 실패 등) — 다음 회차가 같은 경기 글을 또 만들지 않는다(slug 가 어떤 상태로든 있으면 건너뛰고 보고). → Task 12 `existing_draft_slug_blocks_duplicate`, Task 13 `existing_slug_is_exists`.
