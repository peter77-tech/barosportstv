# WordPress 「경기 리뷰」 자동 발행 — 설계

> 작성 2026-10-22 · 결정: BD(방향·범위·제목·검토 방식·이미지·링크) / AI(그 밖의 세부 — 「AI 판단」 표시)
> 시험(spike) 결과물: 견본 3편 — 이 문서 10절. 시험 코드는 저장소 밖(세션 스크래치)에 있었고 **버린다**.

## 1. 왜

사람들은 네이버에서 「프로야구」를 검색하고 일정 카드의 경기를 누른다. 그러면 네이버가
`2026년 10월 20일 KIA 타이거즈 LG 트윈스` 같은 **경기별 검색어**를 만들어 검색한다.
이 검색어는 경기마다 하나씩, 매일 새로 생기는 롱테일이다. barosportstv.com 에 **그 검색어를 제목에
그대로 담은 경기 리뷰**를 경기마다 하나씩 자동으로 쌓아 이 검색을 받는다.

## 2. 목표

1. 워드프레스에 「경기 리뷰」 카테고리를 만들고, 대상 리그의 **끝난 경기마다 리뷰 1편**을 자동 발행한다.
2. 제목 = `{리그명} {네이버 검색어} 경기 리뷰` — 네이버 검색어는 **한 글자도 바꾸지 않는다**.
3. 본문은 **사실만**: 원본 기록에 있는 것과 그 숫자로 바로 계산되는 값. 승패를 가른 요소를 기록 근거로 짚는다.
4. AI 가 쓰고 **AI 검토자가 원본 기록과 대조**해 통과한 글만 바로 공개한다.
5. SEO·AEO·GEO 에 맞춘 구성(답변 상자·구조화 데이터·내부/외부 링크·대표 이미지).

## 3. 하지 않는 것

- **시작일 이전 경기 소급 작성** — BD: 시작일 = **2026-10-22**. 이날 이후 끝난 경기만 쓴다. 완성 전에 끝난 경기(10-22 ~ 첫 실행)는
  첫 실행이 따라잡되, 네이버 검색어나 기록을 그때 못 구하면 건너뛴다(AI 판단). 기준일은 코드에 상수로 둔다.
- 대상 밖 경기: 해외 리그 전부, K리그2, **KOVO컵 등 컵대회**. **포스트시즌(KBO 가을야구·플레이오프·챔피언결정전)은 포함**(BD 결정)
- KBO 공식 사이트(koreabaseball.com) **자동 수집** — robots.txt 전체 차단 + 약관이 「경기 결과·선수통계」의 자동 수집·2차 가공을 명시 금지
- 네이버에서 **본문 재료**를 가져오는 것 (제목용 검색어만 가져온다)
- FAQ 절과 FAQPage 구조화 데이터 (BD: 글 성격과 맞지 않음. 구글 FAQ 리치 결과도 권위 사이트로 제한됨)
- 경기 사진·리그/구단 로고 사용 (저작권·상표)
- 사람 손 검수 단계 (검토 탈락 글만 임시글로 남아 사람이 볼 수 있다)

## 4. 실패로 보는 것 (기술적으로 돌아가도)

- 본문에 **기록과 다른 숫자·이름**, 또는 기록에 없는 장면·추측·순위·시즌 맥락이 들어간 채 공개된다
- 제목의 검색어가 네이버와 **한 글자라도 다르다** (띄어쓰기 포함 — K리그·KBL 은 `2026년10월18일` 처럼 붙여 쓴다)
- 같은 경기 리뷰가 두 번 올라간다
- AI 가 내부 링크 주소를 지어내 404 로 보낸다
- 실패가 조용히 쌓인다 (검색어 못 찾음·검토 탈락·수집 오류를 아무도 모른다)
- 리뷰 작업이 기존 배포(`deploy.yml`)·경기 일정 갱신을 멈춘다

## 6. 제목 (BD 결정)

```
{리그명} {네이버 검색어 그대로} 경기 리뷰
KBO리그 2026년 10월 20일 KIA 타이거즈 LG 트윈스 경기 리뷰
V리그 남자부 2026년 10월 19일 OK저축은행 읏맨 배구단 현대캐피탈 스카이워커스 배구단 경기 리뷰
KBL 2026년10월21일 서울 삼성 썬더스 부산 KCC 이지스 경기 리뷰
```

- 검색어는 네이버 검색 결과 페이지의 경기 링크(`query=...`)에서 그대로 뽑는다. 원본 HTML 에 들어 있다(JS 불필요).
- 네이버 표기는 규칙으로 맞힐 수 없다 — 같은 경기 안에서도 긴 이름·짧은 이름이 섞이고(`스카이거너스` 단독 표기 등),
  날짜 띄어쓰기가 종목마다 다르다. **만들지 말고 가져온다.**
- 우리 경기와 네이버 검색어를 짝짓는 방법은 builder 에게 맡긴다(날짜 + 두 팀이 같은 경기). 짝이 하나로 정해지지 않으면
  쓰지 않는다.
- 🔴 **한 경기에 검색어가 두 형식으로 들어 있는 경우가 있다** (KBL 실측): 앞으로 열릴 경기마다
  `2026년10월23일 수원 KT 소닉붐 원주 DB 프로미` 와 `2026년 10월 23일 원주 DB 프로미 수원 KT 소닉붐`(날짜 띄어쓰기·팀 순서 다름)이 함께 있다.
  끝난 경기에는 한 형식만 남아 있었다. **BD 가 누르는 일정 카드의 링크**를 골라야 한다.
  ✅ BD 확인(2026-10-22, 화면 캡처): KBL 일정 카드를 누르면 **`2026년10월23일 수원 KT 소닉붐 원주 DB 프로미`**(날짜 붙여 씀) 형식이 검색된다.
  → 페이지에서 링크가 놓인 위치(일정 카드 영역)로 가려내고, 그래도 두 형식이 남으면 쓰지 않는다.
  리그마다 「일정 카드의 형식」을 저장된 실측 페이지로 테스트한다.
- 검색에 쓰는 네이버 질의어(리그별 「○○ 일정」, KBO 포스트시즌은 단계별 「프로야구 ○○ 일정」)는 코드에 표로 둔다.
- **검색어를 못 찾으면 그 경기는 건너뛴다** (AI 판단). 다음 회차에 다시 찾고, 경기일 다음 날이 지나도 없으면 포기하고 기록한다.
- 제목 검사는 AI 가 아니라 **코드**가 한다 — 「리그명 + 공백 + 검색어 + 공백 + 경기 리뷰」와 완전히 같아야 발행.

## 7. 본문 구성

### 7.1 순서 (BD 승인한 견본 2판 기준, FAQ 제외)

1. 메타 줄 — 리그 · 날짜 · 장소 · 관중 · 기록 출처
2. **한눈에 보기**(답변 상자) — 2~3문장: 누가, 몇 대 몇으로, 왜. 첫 문장에만 **네이버 검색어 속 정식 팀명**과 날짜를 넣는다
   (AI 판단 — BD 확인 완료). + 핵심 3줄(각 줄 숫자 1개 이상)
3. 이닝별/쿼터별/세트별/전·후반 **점수판** — 코드가 그림
4. `{원정} vs {홈} 경기 흐름` — 기간별 점수 변화
5. **승패를 가른 요소** — 소제목 3개. 각 「주장 → 근거 숫자 2개 이상 → 승패와의 연결」
6. **팀 기록 비교** — 막대 표, 코드가 그림. 리그마다 승패와 관계 큰 항목 **8줄 이내**(BD: KBL 12줄은 많다)
7. **선수 활약**(선수 기록이 있는 리그만) + **주요 선수 표**(코드가 그림)
8. 득점·경고 타임라인(K리그) / 세트 흐름(V리그) 등 리그별 보조 표 — 코드가 그림
9. **총평** — 2문단. 이긴 팀이 잘한 점, 진 팀이 아쉬웠던 점을 숫자로. 미래 예측 금지
10. 출처 줄 — 「{출처} 공식 기록을 바탕으로 자동 작성·사실 검수」(BD: 자동 작성 표기 찬성) + 외부 링크 1개(8절)

- 본문 팀명은 **우리 사이트 표기**. 정식 팀명은 2번 첫 문장에만. (AI 판단) 사이트 팀 목록(`assets/teams.js`)에는 KBO·K리그 팀만 있다 →
  KBO·K리그1은 `teams.js`/`data.js` 가 정한 이름, **KBL·WKBL·V리그는 각 공식 기록의 짧은 팀명**(예 `서울 삼성`·`부산 KCC`)을 쓴다.
  `teams.js` 는 건드리지 않는다(사이트 검색·팀 고르기가 같이 바뀐다). K리그 중복 행(`전북`/`전북 현대`)은 `data.js` 가 고르는 쪽을 따른다.
  대표 이미지 글자도 같은 이름을 쓴다.
- 분량: 본문+총평 1,400~2,600자 (KBO 는 재료가 적어 짧다 — 억지로 늘리지 않는다).
- **표·점수판·막대·구조화 데이터는 AI 가 아니라 코드가 원본 숫자로 그린다.** AI 는 문장만 쓴다.
  (표의 숫자를 AI 가 옮겨 적다 틀릴 위험을 없앤다.)

### 7.2 쓰는 AI 의 금지 규칙 (시험에서 검토자가 실제로 잡은 것)

- 기록에 없는 것: 장면·분위기·감정·인터뷰·부상·전술 의도·순위·시즌 성적·과거 전적·다음 경기
- 원본에 없는 세부: 슛 위치(골밑·중거리), 득점 경로(스틸에서 시작), 선수별 기간 득점, 리드 변화 과정(「경기 내내 앞섰다」 —
  KBL 은 최대 리드 기록으로 반박된다), 수비 평가(「깔끔한 수비」)
- 인과 단정: 「~때문에 이겼다」, 한 요소가 점수 차를 「설명한다」. 비교로 쓴다(「어시스트 27-16으로 앞섰다」)
- 기간별 승패 개수(「몇 쿼터를 이겼다」)는 각 기간 점수를 다시 대조한 뒤에만
- 「기록에 없다」「데이터상」처럼 자료를 의식하는 말투
- 진 팀이 앞선 기록이 있으면 함께 적는다

### 7.3 원본 기록 다듬기 (코드, AI 판단)

- 추가시간: K리그 기록의 `전반 54'` → `전반 45+9분` (실측: 공식 기록이 추가시간을 그대로 분으로 준다)
- 교체: `A (OUT) → B (IN)` (실측: 기록의 첫 선수가 나간 선수 — 출전 시간과 일치)
- K리그 API 는 `Accept-Language: ko` 가 없으면 **영문 이름**을 준다
- TheSportsDB 장소·팀명은 영문 → 한글 표로 바꾼다(`Jamsil Baseball Stadium` → `잠실야구장`)
- K리그 합계 행의 비율 항목은 선수 비율을 더한 값이라 쓸 수 없다 → 성공/시도로 다시 계산
- AI 에 넘기는 선수는 기록이 두드러진 선수로 줄인다(시험: K리그 33명 전원을 넘기자 응답이 5분을 넘겨 연결이 끊겼다)

## 8. 링크 (BD 결정)

- **내부 링크**: 코드가 **표로** 정한다. AI 는 주소를 만들지 않는다. 리뷰 외 링크는 한 글에 3~4개까지.

| 리그 경기일정 페이지 | `/kbo/` `/kleague/` `/kbl/` `/v-league/` | 있으면 항상 (WKBL 페이지 없음) |
| 팀 페이지 | `/samsung/` `/hanwha/` | 그 팀 경기일 때만 |

- **태그**: 리그 태그 1개 + 두 팀 태그(우리 사이트 표기). 같은 팀 리뷰 묶음이 생긴다.

## 9. 검토와 발행 (BD 결정)

```
경기 종료 확인 → 네이버 검색어 찾기 ─(없음)→ 건너뜀(다음 회차 재시도)
   → 원본 기록 받기 → 쓰는 AI → 코드 검사(제목·금지어·HTML) → 사실 검토 AI
        ├ 통과 → 대표 이미지 생성·업로드 → 바로 공개
        └ 탈락 → 지적 사항을 붙여 1회 다시 쓰기 → 검토
                 ├ 통과 → 공개
                 └ 탈락 → 임시글로 저장(지적 사항 함께 기록)
```

- 검토자는 **사실 확인 1명**(AI 판단 — BD 승인). 반론·독자 시선 검토자는 두지 않는다(사실이 전부인 글).
- 검토자는 원본 기록 + 리뷰 모든 필드(메타 설명·한눈에 보기·핵심 3줄·본문·총평)를 대조하고, 계산값은 직접 계산한다.
- 코드 검사(AI 아님): 제목 완전 일치, 본문 숫자가 원본 기록에 있는 숫자이거나 그 차·합·비율인지, 허용 태그만 썼는지.
  세부 방식은 builder 에게 맡긴다.
- 모델: 시험은 쓰기·검토 모두 `claude-sonnet-5-5`. 최종 선택과 비용 계산은 계획 단계(시험 토큰 실측: 쓰기 입력 1~4천·출력 4~6천,
  검토 비슷한 규모, 글당 2~4회 호출).
- **API 응답은 스트리밍으로 받는다** — 한 번에 받으면 긴 응답에서 연결이 끊겼다(시험 실측, `UND_ERR_SOCKET`).
- 같은 경기 중복 방지: 경기마다 고유한 글 주소(slug)를 정하고 발행 전 존재 여부를 확인한다(AI 판단 — 방식은 builder).
- 실패 알림: 검색어 못 찾음·검토 탈락(임시글)·수집 오류를 실행 요약에 남기고, 쌓이면 보이게 한다. 수단은 builder.

## 12. 워드프레스 연동

- REST + 애플리케이션 비밀번호. 🔴 `WP_USER` 는 로그인 아이디 `barosportstv`(재개 문서 참고). GitHub 에는 새 Secret 으로 넣는다.
- 카테고리 「경기 리뷰」(slug 는 builder — 예 `match-review`)는 없으면 만든다. 지금 카테고리: `guide`(무료 시청 가이드) 하나.
- **SEO 플러그인은 Rank Math** (2026-10-22 확인: `rankmath/v1` 네임스페이스, 테마 주석 「Rank Math가 소유한다」).
  - 메타 설명·포커스 키워드(=네이버 검색어)는 Rank Math 메타로 넣는다.
  - Rank Math 가 Article 구조화 데이터를 이미 낸다 → 우리는 **SportsEvent 만** 더한다(중복 금지). 넣는 방법은 builder(본문 JSON-LD 또는 테마).
- 표·막대의 모양(CSS)은 테마에 둔다. 🔴 재개 문서 규칙: **새 Tailwind 클래스를 쓰지 마라** — 리뷰용 스타일은 테마의 일반 CSS 로.
- **테마 반영은 10차와 같은 방식**(AI 판단 — 10차 계획 Task 6): 버전을 올린 테마 zip 을 만들고 **BD 가 관리자 화면에서 업로드**한다.
  사람 손이 필요한 단계이므로 계획에서 한 번에 모은다. 테마에 들어갈 것: 리뷰 표·막대 CSS,
  REST 로 쓸 수 있는 Rank Math 메타에 `rank_math_focus_keyword` 추가(지금 `functions.php` 는 title·description 만 연다),
  SportsEvent JSON-LD 를 테마에서 낼지 본문에 넣을지는 builder.
- 🔴 사이트는 **2026-12-01 까지 noindex**(의도). 그 전에 올라간 리뷰는 출시일 색인 해제 후 검색에 잡힌다.
