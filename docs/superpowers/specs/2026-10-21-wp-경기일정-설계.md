# WordPress 경기 일정 페이지 — 설계

> 작성 2026-10-21 · 결정: BD(방향·별도 페이지) / AI(그 밖의 세부 — 「AI 판단」 표시)

## 1. 왜

barosportstv.com 은 Cloudways 의 WordPress(앞단 Cloudflare)로 운영된다. 경기 데이터는
GitHub Actions 프리베이크가 30분마다 GitHub Pages(`peter77-tech.github.io/barosportstv/data/`)에
굽고 있지만 **WordPress 에는 한 건도 들어가지 않는다** (2026-10-21 실측: `barosportstv.com/data/manifest.json` 404,
페이지에 데이터 칸 0개). BD 는 경기 일정을 **별도 페이지**로 두기로 했다.

## 2. 목표

1. barosportstv.com 에 경기 일정 페이지 하나 — 오늘부터 5일, 날짜·리그로 고른다.
2. **경기 정보가 서버에서 완성된 HTML 로 나간다** (검색엔진이 JS 없이 읽는다).
3. 판정 로직(상태·시각·한글 팀명·리그 등급·정렬)은 **`assets/data.js` 하나에만** 있다. PHP 로 다시 쓰지 않는다.
4. GitHub 쪽이 실패해도 페이지는 **마지막으로 받은 데이터**를 보여 준다.

## 3. 하지 않는 것

- 경기 상세·팀 허브·하이라이트·알림 버튼 (WordPress 에 그 화면이 없다)
- 실시간 점수 (지금처럼 최대 약 40분 늦다 — 갱신 시각을 화면에 적는다)
- 색인 차단 해제 (BD: 소프트런칭 2026-12-01 까지 의도된 차단)
- GitHub Pages 정적 화면 정리 (데이터 보관소 역할은 유지 — 별도 작업)

## 4. 실패로 보는 것 (기술적으로 돌아가도)

- 한국 시각 자정 근처 경기가 엉뚱한 날에 나온다
- 데이터가 몇 시간째 멈췄는데 「진행 중」이 그대로 떠서 사실처럼 보인다
- GitHub 이 오류 페이지를 주는 순간 일정이 텅 빈다
- 「전체」에서 1,000줄이 한 화면에 쏟아진다 (8차 실측: DOM 18,242노드)

## 5. 구조

```
[GitHub Actions] prebake.mjs ── ③ 뒤에 ──▶ tools/lib/wpschedule.mjs
      data.js 를 vm 에서 그대로 실행 (TZ=Asia/Seoul) → data/wp/index.json + day-YYYY-MM-DD.json ×5
            ▼ (GitHub Pages 에 함께 배포)
[WordPress 크론 10분] wp_remote_get → 검증 → 옵션에 저장 (실패 시 이전 것 유지)
            ▼
[page-templates/schedule.php] ?d=날짜 &l=리그 &p=쪽 → PHP 가 HTML 로 출력 + JSON-LD
```

### 5.1 데이터 계약 (`data/wp/`) — AI 판단

`index.json`
```json
{ "generatedAt": "2026-10-21T04:52:56.458Z", "timezone": "Asia/Seoul", "days": ["2026-10-21", "…5개"] }
```

`day-2026-10-21.json` — 그날 **전 경기**, `byInterest` 순서 그대로
```json
{ "date": "2026-10-21", "events": [ {
  "id": "2388800", "sport": "Baseball", "league": "MLB", "leagueLabel": "MLB",
  "slug": "mlb", "tier": 1, "state": "live|upcoming|postponed|finished",
  "clock": "19:05 | 9회 | 연기 | 시간 미정", "home": "텍사스 레인저스", "away": "…",
  "homeScore": "3", "awayScore": "2", "kickoff": "2026-10-21T10:05:00Z"
} ] }
```
- 경기가 없는 날도 `events: []` 로 **파일을 만든다** (없으면 WordPress 는 실패로 본다).
- `homeScore`/`awayScore` 는 `live`·`finished` 일 때만 값, 그 밖에는 `null`.
- 「오늘/내일」 같은 상대 라벨은 넣지 않는다 — 보는 시점에 PHP 가 계산한다.

### 5.2 WordPress — AI 판단

- 데이터 주소 상수 `BSTV_SCHEDULE_SOURCE` = `https://peter77-tech.github.io/barosportstv/data/wp/` (필터 `bstv_schedule_source` 로 바꿀 수 있음).
- 저장: 옵션 `bstv_schedule_meta`, `bstv_schedule_day_<날짜>` (autoload 끔). 새 index 에 없는 날짜 옵션은 지운다.
- 갱신: WP 크론 10분 간격. 저장된 데이터가 하나도 없으면 페이지 요청 때 한 번 직접 받는다(타임아웃 5초).
- 검증 실패(HTTP≠200, JSON 아님, 필드 누락) → **아무것도 바꾸지 않는다.**
- 페이지 템플릿 `Template Name: 경기 일정`. BD 가 페이지를 만들고 템플릿을 고른다(본문은 소개 글로 쓰인다).
- 날짜·리그 칩은 **`<a>` 링크** (`?d=`, `?l=`). JS 없이 동작하고 각 조합이 크롤링된다.
- 리그 판정은 `app.js` `matches()` 와 같은 3줄 규칙: `all` 전부 · `top` = tier 1 · 그 밖 = slug 일치. 기본값 `top`.
- 한 쪽 150행, 넘으면 `?p=` 쪽 나눔.
- `generatedAt` 이 **2시간** 넘게 지났으면 안내문을 띄우고 「진행 중」 배지를 「확인 필요」로 바꾼다.
- 구조화 데이터: 화면에 그린 경기만 `ItemList` > `SportsEvent` (최대 100건). 오래된 데이터면 내보내지 않는다.
- 페이지 캐시: 이 템플릿은 Breeze 페이지 캐시에서 뺀다(`DONOTCACHEPAGE`). 데이터는 이미 옵션에 있어 렌더 비용이 작다. 배포 후 응답 헤더로 확인하고, Varnish 가 계속 잡으면 Cloudways 의 제외 URL 에 넣는다.
- 시간대는 **Asia/Seoul 고정** (한국 시청자 대상).

## 6. 지켜야 할 기존 규칙 (다음세션_재개.md 1절)

- 테마의 `assets/tailwind.css` 에 **없는 클래스는 쓰지 않는다** (규칙 10). 마크업은 `schedule.html` 의 행·칩 클래스를 그대로 옮기고, 각 클래스가 테마 CSS 에 있는지 먼저 확인한다.
- 정적 사이트의 `data.js`·`app.js` 동작은 바꾸지 않는다 — 기존 테스트 57개가 그대로 통과해야 한다.
- API 키는 GitHub Secret 에만 둔다. WordPress 는 공개 JSON 만 받는다.

## 7. 함께 고치는 것

- 배포 산출물의 `CNAME` 제거. Pages 가 커스텀 도메인을 강제하면 github.io 가 barosportstv.com(WordPress)으로 넘어가 **WordPress 가 자기 자신에게서 데이터를 찾다 404** 가 된다.

## 8. BD 가 할 일 (배포 후)

1. 테마 zip(v0.2.0) 업로드 → 교체
2. 페이지 「경기 일정」 생성, 템플릿 「경기 일정」 선택, 메뉴에 연결
3. (필요 시) Cloudways Varnish 제외 URL 에 그 페이지 추가
